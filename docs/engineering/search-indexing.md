# 搜索索引同步与恢复

MySQL 中文章的当前状态、slug 和关联关系是事实来源，Meilisearch 是可重建的搜索投影。搜索文档以文章 ID 为主键，修改 slug 不产生第二篇文档。

## 生命周期

统一单篇入口是 `IndexPostCmdExe.execute(postId)`：当前状态为 `PUBLISHED` 时写入最新标题、纯文本正文、slug、分类、标签和专栏名称；草稿、已删除或数据库中不存在的文章移除索引文档。不能直接把草稿传给搜索端口写入。单实例内同步串行执行，防止旧写入晚于删除完成而重新写回文档；数据库写入仍独立于该锁。若未来扩展为多实例，需要重新设计跨实例投影的并发控制。

- 新建文章默认是草稿，不进入公开搜索；发布后同步。
- 修改标题、正文、分类、slug、标签及专栏归属后同步。
- 共享标签改名或删除时刷新所有受影响的已发布文章；删除专栏前记录关联文章，再刷新解除归属后的文档。
- 专栏顺序、精选状态不属于搜索文档字段，不触发无意义的索引写入。
- 搜索展示再次核对数据库发布状态，并使用当前 slug；索引滞后不能使不可公开的文章出现在搜索结果中。这个检查不是索引清理的替代品。

回归测试：应用层 `SearchLifecycleTest`、`MutationSearchSyncTest`；底层 `MeiliSearchPostIndexerTest`；真实数据库与搜索服务链路由 staging 的 `SearchIndexLifecycleIT` 验证。

## 任务与失败边界

Meilisearch 的写入和删除响应只表示任务已入队。端口必须读取 `taskUid` 并核对终态：仅 `succeeded` 算成功；`failed`、`canceled`、响应无效、网络错误、等待超时和线程中断均使调用失败，不得吞异常或返回成功。删除时明确的 `index_not_found` 表示目标已不存在，按幂等成功处理；写入、任务查询及其他错误不享有该例外。

连接超时为 3 秒，单次读取超时为 5 秒，任务等待期限为 30 秒，每 100 毫秒查询一次。已取得合法 `taskUid` 后，状态 GET 的 `SocketTimeoutException` 在整次等待中最多恢复一次：仅重新查询同一个任务，不重发 POST/DELETE、不重置期限；期限已过不发新请求，线程中断立即停止。第二次读取超时、其他网络错误、HTTP 错误、无效响应及失败终态仍使调用失败。等待可能比期限多出一次受限的读取耗时。超时表示结果未知，不等于服务端任务已取消；写入请求本身的超时绝不自动重发。

数据库写入与搜索任务不构成同一事务。搜索失败时数据库变更可能已保存，页面会报告失败；不得据此重复创建文章，也已发布文章的发布重试只同步索引，不重新发布或重写发布时间；不得恢复已删除内容。以后台当前文章状态为准，用同一文章 ID 重试同步，或执行全量 reindex 修复。需要重试删除标签或专栏后的索引时，用全量 reindex，因为原关联关系已经移除。

## 全量核对

后台既有 `POST /admin/search/reindex` 入口保持不变。它先完整读取配置索引中的文档 ID，使用数据库单次查询取得已发布文章 ID 快照并刷新，再核对剩余 ID 的数据库现状，清理非发布及不存在的文章。先读取后删除避免 offset 分页因删除移动而漏掉文档。不会删除索引、清空全部文档或改动索引设置。同步入口统一每 100 个文章 ID 分批提交更新及删除；每批只等待对应任务终态。全量核对以及共享标签、专栏变更不得逐篇提交并等待，以免累计轮询延迟超过网关请求预算。

只有整次同步完成后才返回 `status=ok`；过程中失败会中止。部分已成功同步的文档保留，可以重试；不能把失败的索引枚举当作空索引。新建环境中明确的 `index_not_found` 可视为空索引。

搜索保留 Meilisearch 的排名、高亮和估算总数。数据库校验只影响当前页，索引尚未恢复时可能出现不足一页的结果；当前页已过滤的命中会从估算总数中扣除，其他页残留仍可能影响估算。全量核对恢复索引后该差异消除。

## 已确认故障与修复操作

逐篇任务等待曾使 862 篇已发布文章的生产全量核对返回 504，客户端超时并不证明服务端已停止。离线回归用 1000 篇文章验证更新任务数不超过 10；staging 用 1000 篇真实数据验证核对在 55 秒预算内完成，并核对全部文档 ID。

历史删除命令只保存 `DELETED`，未删除索引；旧全量 reindex 又仅写入已发布文章，不能清理残留。结果是搜索命中已删除文章，匿名文章详情返回 404。历史 slug、标签和专栏变更入口也缺少索引同步。

修复版本上线并通过环境验证后，通过管理员认证调用 `/admin/search/reindex` 修复历史投影，核对任务成功和搜索结果。生产修复前必须先完成 staging 的隔离测试，不能将本机或 production 检查充作 staging 验收证据。鉴权与 CSRF 使用现有后台规则，不在文档中保存凭证。

2026-10-19 staging E2E 三次在清理文章时遇到任务状态读取超时。新增诊断确认任务 7511 在服务端约 20ms 已成功，服务无重启/OOM，健康请求约 4ms；服务日志未记录对应 Java 状态 GET，而 Java 5 秒后报超时。这个证据限定为一次状态读取未确认成功，不能据此称为任务失败、扩大内存或重复写入；底层 TCP/客户端连接触发原因尚未完全证实。回归模拟“已接受删除 → 状态读取超时 → 同 UID 成功”，并验证恢复预算不被 pending 重置、持续超时和终态失败继续失败、原期限及中断不变、写入永不重发。
