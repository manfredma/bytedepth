# 阅读批注锚定设计

> 状态：书面设计已确认，尚未实施。架构取舍见 [ADR-0024](decisions/0024-versioned-annotation-selectors.md)；当前实现仍遵循 [ADR-0011](decisions/0011-rendered-text-annotation-anchors.md)。
> 导航：[项目知识库](../README.md) · [统一语言](ubiquitous-language.md) · [批注权限](../security/annotation-write-permissions.md)。

## 目标与保证

保留当前划线、评注、四种颜色、匿名归属、公开/私有与侧栏体验，修复正文编辑和客户端渲染使批注错位、丢线、误隐藏的问题。严重错误必须被离线单测拦住，不能等 staging 才发现。

安全规则：

1. 原始引用、创建依据和评注正文不因定位失败而删除或被更新后的文字覆盖。
2. 只有原文校验与版本关系均成立时才绘制；找不到、无法判断或出现多个等价候选时保留记录并明确未定位。
3. 辅助按钮、行号、语言名、SVG、语法高亮 token 和布局变化不能改变正文坐标。
4. 私有与匿名归属规则在定位失败、迁移、版本回看时同样生效。
5. 不承诺任意改写后恢复原语义身份。两份完全相同的文本被删除、复制、重排且没有编辑日志时，系统不猜测身份。

非目标：接入 Hypothesis 账号或托管服务、更换侧栏、改造 Obsidian 编辑器、协同编辑、公开文章版本历史、全文模糊语义匹配、管理员获得他人私有批注权限。

## 成熟实现接入边界

固定 Hypothesis client `a7b7400d0d706d4357ec37c2a3610b25dcca89d5`，仅适配 `src/annotator/anchoring/text-range.ts` 与 `trim-range.ts` 的 DOM 范围转换。它们无外部运行时依赖，处理纯内容根中的文本节点拆分、合并和包装。

实现放在 `static/vendor/hypothesis-anchoring/`，包含上游原始文件、完整许可证、SHA-256 来源清单，以及去除 TypeScript 类型和封装模块导出的 JavaScript 适配文件。保留原算法，局部改动逐项记录；运行时不从 CDN 或浮动分支加载。不为这两个工具引入完整应用构建系统。适配产物由 `scripts/build-hypothesis-anchoring.mjs` 复现，复用并显式固定现有开发工具 rolldown 1.2.5，仅用于类型擦除和模块包装；浏览器不加载编译工具。`scripts/verify-hypothesis-anchoring.mjs` 校验完整上游文件、许可证、逐文件摘要与可复现产物。升级时必须运行上游适用测试与本设计矩阵。

上游 `html.anchor()`、`matchQuote()` 不直接接入。其默认近似匹配能把 `quick brown fox` 匹配到 `quick brown fax`，重复候选也可能由旧偏移决定；这是恢复率取舍，不满足本产品的严格身份规则。产品选择器解析和精确证据策略由独立适配层负责，不伪称来自上游保证。

## 单一正文模型与映射

服务端新增 `ArticleDocument`：Markdown 只解析一次，由同一 AST 生成正文模型、文本投影和 HTML。将已有通用 Markdown 与代码块渲染组件收敛至 app 层的文档服务；adapter 保留页面和输入适配。domain 只保存值对象，infrastructure 实现存储端口，不新增 Maven 模块或反向依赖。

正文模型提供按阅读顺序排列的纯内容片段：片段 ID、类型、正文、全文起止位置、所属块及其文本摘要。片段 ID 只在同一正文版本内有效，不把段落序号或文字哈希当成跨版本身份。HTML 以受 sanitizer 保留的内部属性对应这些片段；正文属性来自服务端 AST，不接受原始 HTML 注入。

`projectionVersion=1` 的规则固定为：Unicode 码点计数、LF 换行、HTML 实体按 DOM 解码后计数；不做 NFC/NFD 合并、不压缩空格、不吞 NBSP；块间使用明确的换行分隔（前块已以 LF 结尾时不重复添加）；同一表格行的单元格以 TAB 分隔。软换行、硬换行、表格单元格分隔、列表和脚注在共享 fixture 中列出完整预期文本。服务端 Java 和浏览器不得各自从任意 HTML 去标签推导文本。

正文、行内代码、普通代码源码及实际可读脚注正文可作为文字目标。工具栏、语言标签、复制/折叠按钮、行号、脚注导航符号、批注自身的卡片和标记层不计入。Mermaid/公式生成节点整体排除；Mermaid 图形内部不提供文字划线，已有源码批注保留记录并标记当前无可显示文字范围，图表前后正文不受影响。不将这一边界声称为新增图表整体批注功能。

浏览器维护片段至当前 DOM 的双向映射。块内复用上游工具，UTF-16 DOM 坐标与持久化码点位置只在适配器中转换；跨块选择表示为若干纯内容范围，不用一个跨越工具栏的 DOM Range。缺失片段、未知投影版本、映射结果文字不符时禁止提交或绘制，并保留未提交输入与已保存记录。

## 数据模型与状态

沿用文章 `contentVersion` 的现有递增语义，新增不可变 `PostContentRevision`，保存 `(postId, contentVersion)`、Markdown、正文模型、投影版本和内容摘要。标题变更而正文不变仍可生成对应版本，正文数据允许按内容摘要去重，但版本关联必须独立存在。上线时为当前版本建立基线，不伪造过去版本。

`PostAnnotation` 增加原始锚点：协议版本、创建正文版本、精确引用、前后各最多 128 个码点上下文、片段范围及规范化文本位置、请求幂等 ID。上下文截断不切断代理对；不把固定上下文长度当作消除歧义的证明。原始锚点写入后不可变。

当前版本的定位使用 `AnnotationPlacement`，与原始锚点分离。键至少包含 annotation、目标正文版本、投影版本与 resolver 规则版本。记录定位状态、候选范围与原因；目标版本变化时不得复用旧 placement。缓存可以删除重建，不能影响批注原始记录。

| 状态                | 用户可观察行为                                                   |
| ------------------- | ---------------------------------------------------------------- |
| `ANCHORED`          | 核验后显示划线；有评注则按现有模式显示                           |
| `UNRESOLVED`        | 无可确认目标，不画线；保留引用和评论，侧栏明确“原文已变化”       |
| `AMBIGUOUS`         | 多个位置无法区分，不画线；保留引用和评论，显示“无法确认原位置”   |
| `LEGACY_UNVERIFIED` | 历史依据不足，只向现有创建者显示待确认记录，不自动恢复为公开批注 |

纯划线没有评论时，同样保留原引用，侧栏增加独立的“未定位摘录”入口，默认折叠；不把纯划线混入带评注列表。未定位评注放入独立区域，不占正文跟随位置。已有公开/私有设置保持，历史隔离状态不自动扩大可见范围。

`deleted` 不再表达定位失败。只有用户明确删除才进入删除流程；删除后的记录不会因重定位重现。当前实现的用户删除使用 repository delete，而 `deleted=true` 来自自动重算；迁移时仍按已有数据来源逐项核对，不凭这个概括批量恢复公开状态。

历史快照默认仅供内部定位使用，不新增公开历史正文 API。回看原引用继续受批注可见性和当前文章访问权限控制，不因批注公开而公开整份历史正文。

## 定位规则

app 层是跨版本定位的唯一权威实现；浏览器只提交经过映射的选择器，并核验服务端返回的当前版本 placement，再转换为 DOM 范围。浏览器不再维护第二套跨版本搜索或评分算法。第三方工具负责块内 DOM 转换，不能绕过服务端的身份判断。

同一正文版本：校验版本、片段、范围、引用和上下文；位置不是唯一证据，任何不符都不能直接画线。

跨版本：比较不可变源版本与目标版本的结构化块和文本，生成可审计的映射关系。只有同一选区的文字保持不变，且其所属内容块的对应关系能唯一确认时，才接受迁移；前文插入和唯一块移动可保留。位置只用于候选检索和性能优化，不能打破歧义。

纯粹“新文中恰好只剩一个相同句子”不构成身份依据：原句可能已删除，另一个同文句子被保留。若旧版本存在多个等价出现位置，块的前后结构、上下文与变化映射不能消除歧义，则返回 `AMBIGUOUS`。diff 库给出的单一对齐结果不是唯一性证明。

选区内部删除、替换或插入均不自动扩大、缩小或改写原引用，返回 `UNRESOLVED`；选区外的变化可按上述规则迁移。搜索无匹配、仅近似匹配、映射预算耗尽、版本缺失均保留记录并返回明确原因。候选搜索设定有界预算，超限终止而不回退到随便选择第一个候选。

首个版本不新增手动重新关联接口；原引用和评论始终保留，允许创建者继续编辑评注、改变可见性或删除。后续若增加重新关联，应保存新锚点关系及原始引用，不能覆盖来源。

## 写入、一致性和重试

创建请求必须携带协议版本、当前正文版本、正文模型摘要、完整 quote/context/position、请求 UUID。服务端从自己的正文模型核验，不信任客户端提供的引用或身份。

旧页面遇到版本变化返回 `409`，前端保留选中文字和正在输入的评论，提示刷新后重试；不自动把旧坐标解释成新版本。校验失败为 `422`，未知协议版本拒绝写入。CSRF 刷新后重试复用原请求 UUID。

通过 app 定义原子写端口，由 infrastructure 在短数据库事务中锁定文章行，重新核对版本，完成批注写入或正文版本更新；这两类操作遵循同一文章行锁顺序，不能只在锁外比较版本。幂等键按文章与创建者身份作用域唯一；相同 ID 与相同载荷返回原结果，相同 ID 不同载荷拒绝。唯一索引兜底并发重复。

正文保存与不可变版本快照在同一事务提交。定位失败不阻断正文更新且不修改原批注；当前 placement 按指定目标版本重建。读取不得展示与页面版本不一致的 placement。失败或超时返回未定位状态，不删除评论。搜索索引更新继续使用现有职责边界，不把外部索引操作纳入持锁事务。

## 渲染生命周期

普通正文先可用，Prism、Mermaid 各自在局部组件渲染完成后注册或重建映射。渲染错误不阻塞其他内容块；代码高亮失败而源码仍在时可用源码建立范围。

批注显示统一通过显示适配器完成，不能要求渲染器保留已有 `mark`。Prism token 重建后重建对应范围；Mermaid 完成或失败均不把生成图形文字纳入投影。对未知 DOM 替换由局部观察器触发重建，忽略批注自身标记变化，避免循环。

每次初始化和文档切换具有 generation 标识；旧异步结果只能丢弃，不能把旧文章的范围写回当前文档。清理观察器、监听器、定时器和渲染任务；重复初始化不重复标记和事件绑定。字体、图片、折叠、tab 和窗口变化只请求几何更新，不改变原始锚点。

## 历史迁移与回退

新增 schema，不删除旧字段或篡改旧数据。当前文章建立可追溯基线；旧批注只有在旧坐标解释下能精确还原引用、且当前范围与内容能确认时才迁移，并标注为迁移基线而非伪造创建版本。

缺少历史依据、旧坐标不符、重复文字无法区分、历史自动隐藏记录，转入 `LEGACY_UNVERIFIED`，保留数据但不自动重新公开。保留旧偏移和原数据库字段用于诊断。旧客户端缺少新协议字段时拒绝创建并要求刷新，不静默写回旧坐标格式。

应用回退必须配合数据库备份及协议兼容检查；旧程序不理解新状态，不能直接将新记录交给旧重算器。回退时关闭批注写入并保留数据，不能以清空新字段恢复运行。

### 单测如何跨过实际故障接缝

模型摘要采用确定性的二进制编码后 SHA-256：32 位大端投影版本、全文 UTF-8 长度与字节、32 位片段数；每片段依次为 id/blockId/kind/text 的 UTF-8 长度与字节，以及 32 位大端 start/end。摘要不包含自身；片段顺序为实际阅读顺序。编码变化须审查投影版本兼容性。

共享 fixture 提交在 `scripts/test-fixtures/annotation/`，包含 Markdown 输入、明确的预期文本、正文模型和实际页面 HTML。Java 端将同一输入经真实 `ArticleDocument`、renderer 和 sanitizer 生成结果，与这些经过审阅的 golden fixture 比较；使用 Java 25 进程内测试，不连接 MySQL、Redis 或 HTTP 服务。fixture 更新必须验证明确预期文本，不能静默重录所有结果。输入 Markdown 与输出 HTML 的空白是协议证据，由 `.prettierignore` 精确排除自动重排；JSON 仍正常格式化。这样 JavaScript 单测可直接消费已提交 fixture，不依赖先启动 JVM 或先跑 Maven 才能执行。

JavaScript 的 DOM 单测消费上述同批输入/输出，执行产品选择器、映射、显示、实际仓库 Prism 包与 `code-blocks.js`。Mermaid 在单测中使用受控 promise 和已核实的 DOM 替换 fixture，测试真实替换时序；不 mock 掉锚定算法或声称模拟器验证了 SVG 几何。期望结果包含范围文本、目标身份、保留的记录和状态，而不是只检查是否出现一个 `mark` 标签。

确定性变换测试以 fixture 中独立维护的目标身份为 oracle，不以被测 resolver 的输出反推答案。安全性与恢复率同时检查：不能通过“全部返回未定位”来满足不误挂。关键 mutation 反例包括移除 quote 校验、恢复裸 `textContent` 计数、把歧义改成选第一项、定位失败执行删除、忽略正文版本、接受旧 generation；每个反例都必须使对应单测失败。

门禁接入现有 `npm test`、Maven Wrapper 单测和 `bash scripts/run-local-quality.sh`，无远程凭据也能执行；新增套件零执行或被 skip 不算通过。当前 Vitest 覆盖率 include 未包含 `annotation.js`，实施时必须显式加入该脚本与新定位/映射/生命周期适配模块，不能只让已有四个前端文件的覆盖率继续为 100%。JavaScript 门禁读取覆盖报告，确认这些模块确实有语句和分支被统计。可按组运行快速反馈，但最终仍跑完整门禁。测试失败必须先保留最小 fixture，再修复；不能删断言或调整覆盖范围来通过。

## 集成与 staging 浏览器补充

补充集成测试：真实 Flyway 迁移、唯一索引、并发锁顺序和事务回滚，以及私有/匿名查询过滤。mock/fake 单测不能证明数据库隔离。

补充桌面与移动 staging E2E：创建并清理自有文章，覆盖普通正文、真实 Prism、真实 Mermaid、刷新、插入前言、重复文字、未定位侧栏和权限。它验证真实浏览器选择、SVG 几何、响应式布局及网络交互；已知代码块误删和丢线必须先被 U13/U15/U28/U33 等单测捕获。现有 staging 测试文章只作复核入口，自动化不能依赖其 ID 或残留数据。
