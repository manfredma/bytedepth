# ADR-0012: 文章级导航使用完整页面导航而非局部替换

- **状态**: Proposed
- **日期**: 2026-09-22
- **决策者**: 项目所有者

## 上下文

文章详情页是服务端渲染页面，页面级能力由多个脚本共同初始化，包括批注、划线、图片灯箱、阅读进度、专栏导航和 Mermaid。专栏侧边栏曾通过 `fetch()` 获取下一篇文章，只替换 `#post-article`，再手工重跑部分批注初始化。

这种局部替换只更新了正文 DOM，没有重新执行文章页中声明的脚本生命周期，导致新文章的图片没有绑定灯箱事件；同时 `history.pushState()` 没有配套 `popstate` 恢复逻辑，浏览器前进后退可能只改变地址而不恢复正文。页面级局部替换还会持续增加遗漏初始化的风险。

项目需要明确区分“页面级导航”和“组件级数据刷新”，避免把局部 DOM 更新误用为整篇文章导航机制。

## 决策

文章详情页及专栏内文章之间的导航统一使用原生完整页面导航；不再通过 `fetch()` + `replaceArticle()` 替换整篇文章 DOM，也不新增同类页面级局部刷新实现。普通 `<a href>` 保留浏览器原生的刷新、分享、前进后退、打开新标签页和无障碍语义。

组件内部的局部状态更新和独立数据刷新可以继续使用 DOM 更新，例如批注列表、后台统计图表和运维状态面板，但不得借此替换另一个完整页面或绕过页面初始化生命周期。

放弃继续扩展 `replaceArticle()`，因为它要求每次新增页面脚本都同步维护手工初始化、清理和历史记录恢复逻辑，收益不足以抵消一致性风险。

## 后果

**正向**

- 每次进入文章都会执行完整的服务端模板和前端脚本初始化，灯箱、批注、阅读进度和 Mermaid 不会因局部替换而漏初始化。
- 浏览器原生处理历史记录、前进后退、刷新、分享链接和新标签页打开。
- 页面级导航的生命周期简单，后续新增文章功能不需要修改一个集中式局部替换器。
- 内容指纹资源和 Service Worker 仍可缓存静态资源，完整导航不会重复下载所有脚本内容。

**负向**

- 切换文章会有一次完整页面导航，页面外壳状态、正文滚动位置以及未保存的文章内输入不会保留。
- 需要依赖网络完成页面导航；Service Worker 只能按既定的 network-first 导航策略提供离线回退。
- 不能再依赖局部替换带来的无白屏切换体验。

## 假设

| 假设 | 可证伪信号（出现时重评） |
|------|--------------------------|
| 文章详情页继续由 Spring + Thymeleaf 服务端渲染，且页面脚本数量会继续增长 | 页面改为客户端路由或统一引入可组合的页面生命周期框架 |
| 文章切换的首要目标是功能一致性、可分享和可恢复，而不是无刷新切换 | 真实用户数据表明完整导航造成不可接受的性能或留存损失 |
| 组件级刷新不需要替换完整文章页面 | 需要在同一页面内稳定承载多个独立文章文档并支持跨文档状态共享 |

## 退出条件

| 信号 | 预设行动 |
|------|----------|
| 引入正式的客户端路由和统一页面生命周期管理 | 重新评估文章级导航是否切换为客户端路由，并保留完整导航作为降级路径 |
| staging E2E 连续观测到完整导航性能超过既定预算 | 先测量服务端响应、静态资源缓存和 SW 命中率，再评估有完整生命周期契约的局部导航方案 |
