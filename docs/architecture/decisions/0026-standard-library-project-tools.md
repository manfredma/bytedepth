# ADR-0026: 使用 Python 标准库收敛项目工程工具

- **状态**: Accepted
- **日期**: 2026-10-25
- **决策者**: 项目所有者（确认全量脚本重构设计）

## 上下文

本地质量、版本检查和 Host Agent 测试辅助分散在 Bash、Python 和 Node 文件中。独立包装、重复文本解析和隐式全局状态使一次规则修改需要同时调整多处实现与检查。仅删除历史脚本无法消除仍在使用的重复逻辑。

## 决策

用 Python 标准库包 `tools.bytedepth` 统一工程命令、进程、报告与资源生命周期；依赖 Node 库的资源构建和移动工具保留 Node 实现。工具按职责组织，测试使用标准测试发现，不维护一项检查一个可执行 Shell 文件的模式。

固定的本地入口和 release-platform 仍在使用的 Host 路径可以保留为 exec 适配器，其中不再维护规则。外部消费者未核实前不删除接口。项目产品模块不依赖工具包，不新增 Maven 模块、pip 依赖或任务执行框架。

候选身份、资源隔离、日志脱敏、零告警、测试真实执行数和清理完成后才生成 evidence 的要求不变；发布仍由 release-platform 和 Host Agent 执行，见 [ADR-0022](0022-pr-candidate-staging-before-merge.md)。

未选择只合并 Bash 文件，因为嵌套语言、文本处理和隐式状态仍会保留；未选择新 Node 工具框架，因为 Host 引导不能先依赖候选 npm 工具安装，现有 Python 报告处理也无需引入新框架。

## 后果

- 参数、错误处理、进程与文件操作可以在一处维护，工程测试可统一发现。
- 迁移必须覆盖原有成功及失败检查，不能用删除测试降低质量要求。
- Python 成为工程工具的公共依赖；复用本机和 Host 现有解释器，不能凭默认推荐安装第二套运行时。
- 必需的 Node 模块与框架插件仍需维护；文件移动本身不算复杂度降低。

## 假设

| 假设                                    | 可证伪信号（出现时重评）                  |
| --------------------------------------- | ----------------------------------------- |
| 现有本机与 Host Python 能执行标准库实现 | 已有运行时无法导入或执行工具包            |
| 固定 exec 适配器足以兼容外部入口        | 平台依赖旧脚本的内部函数或特定 Shell 状态 |

## 退出条件

| 信号                                                 | 预设行动                                       |
| ---------------------------------------------------- | ---------------------------------------------- |
| 迁移导致安装新运行时或维护两份规则才能交付           | 缩小实现依赖并重新评审对应接口，禁止长期双实现 |
| 操作入口减少而重复规则、自定义代码和调用复杂度未减少 | 按真实重复职责继续合并，不以文件数宣布完成     |
