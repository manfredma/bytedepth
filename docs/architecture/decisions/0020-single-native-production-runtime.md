# ADR-0020: 单一宿主机原生生产发布与回退

- **状态**: Accepted
- **日期**: 2026-09-26
- **决策者**: 项目所有者

## 上下文

生产当前由宿主机上的 systemd 服务提供应用、公网入口和数据服务。生产发布脚本曾依赖已经退出的运行环境，并在每次发布时复制和同步整套数据库、缓存及搜索数据。这使发布入口与真实回退基线不一致，也增加了故障面。

## 决策

生产只保留一套原生运行时。持久数据继续使用 `/data/bytedepth-native-production`；应用发布使用 `/opt/bytedepth/production/releases/<tag>`，`/opt/bytedepth/production/current` 指向当前不可变 JAR。systemd unit 使用 `bytedepth-production-*` 命名。

常规发布只安装新 JAR、原子切换 `current`、完整重启应用、验证内部与公网 `/version` 并 reload 项目 Nginx。切换失败时恢复切换前的 native `current`，重启并验证原应用；不在应用发布时复制、清空或重灌 MySQL、Redis、Meilisearch 数据目录。

本决策生效时，主机仍使用带临时命名的 unit 和 release 路径。首次按新布局发布时，在部署锁内迁移配置文件、原生 unit 名称和 release 根目录；持久数据库目录原地保留。新应用通过健康检查前保留旧 unit 配置和回退目录，迁移或发布失败时恢复旧配置与旧服务。迁移成功后删除旧名称配置及专用于运行方式切换的脚本、unit 模板和操作文档。

## 后果

- 运行与回退路径直接对应当前 native 服务和上一版 JAR，不再要求两套应用或数据栈并行运行。
- 首次命名迁移会停止并重启本项目的 native 服务；应用发布期间有一次 systemd restart 窗口。
- 数据库迁移必须保持旧应用可兼容，或在发布记录中提供明确、可验证的数据恢复方案；脚本不以旧数据栈代替数据库恢复策略。
- 完成迁移后，普通部署不再安装、检测、调用或记录旧运行方式相关的依赖。
