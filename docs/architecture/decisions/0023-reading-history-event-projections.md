# ADR-0023: 以阅读事件驱动个人阅读历史投影

- **状态**: Accepted
- **日期**: 2026-10-07
- **决策者**: 项目所有者与维护团队

## 上下文

现有 `post_view_log` 记录站点访问和单次阅读进度，但原始明细只保留 7 天，且包含访问分析字段，不能直接作为长期个人阅读历史。新能力需要在文章元数据中展示当前读者的阅读次数、累计有效阅读时长和最近阅读时间，并提供只涵盖文章的历史页。

未登录读者的阅读历史不能上传服务端；登录读者需要跨设备长期保存。二者必须共享一致的业务语义，但不能把匿名浏览器数据隐式上传或与账号自动合并。

## 决策

1. 将“阅读事件”作为个人阅读能力的事实来源，事件类型为打开、有效阅读心跳、完成和离开。每个事件有客户端生成的 `eventId`，服务端按该标识幂等处理，并以服务端接收时间排序。
2. 登录读者的事件写入服务端，原始事件保留 7 天；异步投影为长期的用户-文章阅读历史和当前读者阅读摘要。投影目标延迟不超过 5 秒，事件可重放。
3. 匿名读者使用同一事件语义，但只在浏览器 `localStorage` 保存。匿名原始事件保留 7 天，按文章汇总的本地阅读历史保留最近 1000 篇并按最近阅读时间 LRU 淘汰；不上传、不自动迁移到账号。
4. 文章详情页只显示当前读者自己的阅读摘要：阅读次数、累计有效阅读时长和最近阅读时间。站点 PV、国家/设备访问分析继续由既有访问日志负责，IP、User-Agent、Referer 不进入个人阅读事件或阅读历史投影。
5. 阅读历史只展示当前可访问的已发布文章；文章删除、下架、草稿或读者失权时隐藏对应条目但不删除历史。用户注销账号时删除可关联到该用户的阅读事件和阅读历史投影。
6. 阅读历史 API 不接受客户端传入的用户身份；服务端仅从认证上下文获取用户。匿名本地存储故障时静默降级，不能回退为服务端上传。

## 后果

**正向**

- 个人阅读历史与站点运营访问分析清晰分离。
- 登录与匿名读者获得一致的阅读摘要语义，同时保住匿名数据本地性。
- 原始事件可重放，新的投影或展示口径不需要重新解释旧的访问日志。
- 事件幂等和异步投影可处理网络重试、多标签页和短暂服务故障。

**负向**

- 新增原始事件、异步投影和长期阅读历史的存储与监控成本。
- 登录用户的详情页数据可能在投影延迟窗口内暂时落后，前端需要乐观更新。
- 匿名阅读历史天然不跨浏览器、不跨设备，清除站点数据后不可恢复。

## 假设

| 假设                                      | 可证伪信号（出现时重评）                 |
| ----------------------------------------- | ---------------------------------------- |
| 阅读事件 7 天足以支持投影重放             | 投影积压或修复窗口超过 7 天              |
| 1000 篇本地投影不会造成明显浏览器存储压力 | 常见浏览器出现写入配额失败或首屏读取卡顿 |
| 异步投影 5 秒内可完成                     | 峰值期间投影延迟持续超过 5 秒            |

## 退出条件

| 信号                             | 预设行动                                                 |
| -------------------------------- | -------------------------------------------------------- |
| 需要匿名跨设备同步               | 重新评估明确授权的匿名导入/绑定机制，不能隐式上传        |
| 阅读事件成为计费、奖励或风控依据 | 新增服务端可信时间、反作弊与审计模型，不复用当前轻量模型 |
