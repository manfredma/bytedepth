# 页面级导航完整刷新设计

## 背景

文章详情页由 Spring + Thymeleaf 渲染，并在同一页面加载批注、划线、灯箱、阅读进度、专栏导航和 Mermaid 等脚本。专栏侧边栏当前拦截链接，通过 `fetch()` 拉取完整 HTML 后只替换 `#post-article`，造成新文章未执行灯箱初始化，且浏览器历史记录没有 `popstate` 恢复逻辑。

## 目标

- 专栏侧边栏、文章顶部和底部的文章级链接都走原生完整页面导航。
- 删除页面级 `replaceArticle()` 路径，防止后续新增脚本再次出现漏初始化。
- 保留批注、后台图表和运维面板等组件级数据刷新。
- 用单元测试锁定模板不再加载页面级拦截脚本，用 staging E2E 验证侧栏点击产生真实文档导航。

## 方案

删除专栏导航的点击拦截脚本及其模板引用，保留侧栏中的普通 `<a href>`。浏览器原生导航负责网络请求、历史记录、前进后退、新标签页和无障碍行为。Service Worker 继续按现有页面 network-first、静态资源 cache-first 策略工作。

在前端知识库中记录边界：局部刷新只允许更新独立组件或数据区域，不得替换完整文章页面；后续若引入客户端路由，必须先重新评估并建立统一的页面生命周期契约。

## 测试

- Vitest：验证文章模板不再引用 `series-navigation.js`，避免页面级拦截重新引入。
- Playwright E2E：从专栏进入文章，打开侧栏，点击另一篇文章并等待真实文档导航；验证目标 URL、文章内容和文章脚本正常加载。
- staging：运行全量 E2E，由项目所有者在 staging 验收侧栏导航、灯箱和批注功能。
