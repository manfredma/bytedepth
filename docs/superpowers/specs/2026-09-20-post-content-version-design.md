# 文章内容版本号设计

## 目标

为文章增加轻量版本化元数据：记录当前内容版本号，标题或正文每次实际变化自动递增；公开文章详情页显示 `vN`。不保存历史正文，不提供查看差异或回滚。

## 已确认的产品规则

- 新文章初始化为 `v1`。
- 标题或正文任一字段实际变化时版本号加 1。
- 只修改分类、标签、专栏、Slug 或发布状态时版本号不变。
- 公开文章详情页展示版本号；后台列表和编辑页不展示。
- 现有文章迁移基线：`updated_at <> created_at` 初始化为 `v2`，否则为 `v1`。

## 架构与数据流

`Post` 领域对象新增 `contentVersion`，创建工厂设置为 1，持久化重建接收数据库版本值。`Post.updateContent` 比较标题和正文：变化时更新 `updatedAt` 并递增版本；未变化时保持版本不变。`UpdatePostCmdExe` 保留现有批注重算、保存和已发布文章索引流程。

`PostDO` 增加 `contentVersion`，`PostRepositoryImpl` 在 DO 与领域对象之间双向映射；`PostDTO` 暴露 `contentVersion`，`GetPostQryExe` 映射该字段。Flyway V24 先添加非空字段并完成历史初始化。模板在文章详情页现有发布时间/更新时间元数据行中追加 `版本 vN`，使用现有文章元数据样式，不新增公共组件。

## 一致性与边界

版本字段与文章主记录同事务保存。现有并发编辑行为保持不变，最后写入者覆盖；本次不引入审计快照、乐观锁或冲突提示。版本号只反映标题和 Markdown 正文的变更，非内容操作不会修改它。

## 错误处理

- `content_version` 必须是正整数；领域重建对缺失旧调用参数使用 `1`，数据库列使用非空默认值。
- 文章不存在、权限校验、CSRF 和索引失败行为沿用现有更新链路。
- 迁移只执行一次，使用 Flyway 版本号保证 staging/生产一致执行。

## 验证标准

- 领域单元测试覆盖创建为 1、标题变化递增、正文变化递增、标题正文均不变不递增。
- 更新用例测试覆盖版本递增、无内容变化版本不变、分类变化不递增，以及已发布文章继续索引。
- 查询 DTO 和详情模板测试验证版本值映射与 `版本 vN` 文案。
- MyBatis 持久化单元测试验证 contentVersion 双向映射。
- staging 集成测试验证迁移后文章版本读写；staging E2E 验证公开详情页显示版本元数据。
- 运行本地质量门禁时不得出现任何 `WARNING`。
