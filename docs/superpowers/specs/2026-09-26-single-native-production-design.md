# 单一 native 生产部署设计

## 目标

生产发布与当前运行的 native systemd 服务保持一致：更新不可变 JAR、原子切换 `current`、重启应用并验证公网版本。回滚只使用已验证的上一版 JAR，不复制或重灌持久数据。

## 变更范围

- 将现役 production release、配置和 systemd unit 归一为不带过渡标记的路径与名称。
- 首次部署仅在目标不存在且唯一识别旧目录时迁移现有 release 与配置；数据目录保持原位，并修复绝对软链接目标。
- 移除只服务于运行方式切换的脚本、测试和文档。
- 所有项目文件由 `ubuntu` 持有；服务进程只获得运行所需权限。
- 部署过程不执行数据库备份/复制，不设置整机可用内存门槛。

## 验收

- 契约测试覆盖原位路径迁移、current 软链接修复、不可变制品验证、应用重启、Nginx reload、native 回滚和 ubuntu 所有权。
- staging 部署后检查 `/version`、关键页面、systemd 状态和日志；正常后继续生产部署。
