# 悬浮文章评分组件设计

## 目标

将文章页中重复且占用空间较大的评分卡片，收敛为一个低打扰的固定悬浮评分胶囊；保留现有 1–5 星打分、同浏览器可更新评分和数据持久化行为。

## 布局与交互

- 文章详情页只渲染一个评分组件，不再在正文前后各渲染一次。
- 桌面端组件固定在视口右下角，使用圆角胶囊、轻边框和阴影；默认只展示“文章有帮助吗？”及五颗可点击星星。
- 移动端组件固定在底部居中，宽度按内容自适应，并通过安全间距避免遮挡正文。
- 组件的 z-index 低于现有浮动目录、主题和专栏控件；桌面和移动端分别留出对应的避让距离。
- 点击星星继续提交现有 POST 评分表单；提交后的重定向目标改为唯一组件锚点，用户选中的星级保持高亮。

## 得分展示

- 当 `ratingCount > 0` 时，星级右侧展示平均分，格式为 `4.6 / 5`。
- 当没有评分时，不展示平均分、评分人数或“成为第一个评分的人”等提示文本。
- 首次评分成功后，后续页面加载会显示新的平均分；同一浏览器更新评分时仍由现有唯一键覆盖旧值。

## 实现边界

- 保留现有评分表、应用查询、控制器和 CSRF 表单提交协议，不改动评分数据模型或接口路径。
- 调整评分 fragment 的标记和独立 CSS；所有新增选择器继续以 `post-rating-` 命名空间隔离，不影响其它公共组件。
- `detail.html` 删除一个评分 fragment 调用，仅保留唯一的悬浮入口。

## 测试

- 更新详情页 MVC 测试，保证评分组件模型仍被提供且普通文章访问行为不变。
- 新增模板渲染测试：无评分不输出分数摘要；有评分输出一位小数的平均分。
- 运行完整多模块构建与测试：先 `mvn clean install -DskipTests -Dsort.skip=true`，再 `mvn test -Dsort.skip=true`，均使用 Java 21。
