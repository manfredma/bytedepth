# 首页文章排序与热门页最新补充设计

## 目标

首页文章列表保留按最新发布时间排序，并提供按历史总访问量排序的可选项。热门排序页顶部额外展示三篇最新发布的文章，且这些文章不得与当前页的热门文章重复。

## 范围

- 仅改首页 `/` 的文章列表。
- 默认排序维持为最新发布。
- 热度定义为文章历史总访问量。
- 不改变文章详情页的访问计数、Redis 同步或访问日志行为。
- 分类、标签、文章列表等其他页面不新增排序选项。

## 访问方式与状态

首页使用 `sort` 查询参数表示排序方式：

| URL | 行为 |
| --- | --- |
| `/?page=1` 或 `/?sort=latest&page=1` | 按发布时间倒序，保持现有首页行为。 |
| `/?sort=hot&page=1` | 按历史总访问量倒序显示热门文章。 |

允许值仅为 `latest` 与 `hot`。缺失、空值或未知值一律归一为 `latest`，避免将任意值传至查询层。切换排序时链接固定到第 1 页。

## 数据查询

### 最新排序

复用现有已发布文章查询，按 `post.published_at DESC` 分页；总数继续使用已发布文章总数。

### 热门排序

新增已发布文章的热门分页查询。查询以 `post` 为主表，左连接 `page_stats`：

- 文章统计路径统一为 `/posts/{post.id}`，与 `RedisStatsService.flushToDB()` 的落库路径一致。
- 使用 `COALESCE(page_stats.pv_count, 0)` 处理尚无访问记录的文章。
- 排序为 `pv_count DESC, post.published_at DESC, post.id DESC`，保证访问量和发布时间相同时分页稳定。
- 总数仍为全部已发布文章数；访问量为零的文章也应出现在热门列表的后续页。

热门查询返回的 DTO 增加 `viewCount`，供热门文章卡片展示。最新排序无需展示访问量。

### 热门页的“最新发布”补充区块

仅在 `sort=hot` 时执行第二条查询：

- 查询已发布文章，按 `published_at DESC, id DESC` 排序。
- 排除当前页热门列表中的文章 ID。
- 最多返回 3 篇；可选结果不足 3 篇时正常展示实际数量。
- 该区块不参与热门分页：热门列表页容量固定为 10，分页总数也只针对热门主列表。

在数据库层执行排除，避免应用层为凑足三篇而进行不确定的超量读取。

## 页面交互

文章列表标题旁提供“最新”和“热门”两个排序链接：

- 当前选项以激活样式标识，且不可造成额外布局影响。
- `latest` 时标题为“最新文章”，仅显示原有文章主列表。
- `hot` 时先显示标题为“最新发布”的三篇补充文章，再显示标题为“热门文章”的分页主列表；热门卡片显示总访问量。
- 分页上一页、下一页、页码以及跳页均保留当前 `sort` 参数。为此，首页向现有分页片段传入含 `sort` 的基础 URL。

## 分层职责

- `HomeController`：解析并归一化 `sort`；调用相应查询；在热门模式下触发最新补充查询；向模板提供当前排序和结果模型。
- `ListPostsQryExe`：提供按热门分页和排除指定文章 ID 查询最新文章的应用查询方法；将访问量映射到 DTO。
- `PostRepository`：声明两种查询的意图，不暴露 Web 参数或页面模型。
- `PostRepositoryImpl` / `PostMapper`：实现涉及 `page_stats` 的热门 SQL 与带排除 ID 的最新 SQL。
- `index.html`：渲染排序切换、条件化的最新补充区块和热门访问量。
- `pagination.html`：只接收首页提供的基础 URL，沿用既有拼接逻辑，从而保留排序参数。

## 错误与边界

- `page` 沿用现有约定；排序切换总是从第一页开始。
- 所有热门文章均没有访问量时，结果退化为发布时间倒序，并由 ID 保证稳定。
- 当前热门页包含全部可发布文章时，补充区块为空且不渲染。
- 访问量读取自定时刷入的 `page_stats`，因此热门排序最多会有既有五分钟同步间隔的延迟；不为首页排序额外扫描 Redis。

## 测试

- `HomeControllerTest`：验证默认/非法排序归一为 `latest`，`hot` 调用热门查询并暴露当前排序，热门模式加载最新补充列表。
- 查询层或仓储集成测试：验证热门结果按访问量、发布时间、ID 排序；无统计记录文章的访问量为零且仍可返回。
- 查询层或仓储集成测试：验证最新补充查询排除当前页热门文章，并在不足三篇时返回实际数量。
- 模板或 MVC 测试：验证热门模式显示两个区块与访问量，最新模式不显示补充区块；分页 URL 包含当前 `sort`。

## 非目标

- 不做近 7 天、30 天等时间窗口热度。
- 不新增热度分数、衰减算法、缓存预热或排行榜接口。
- 不修改 `post_view_log` 的分析统计口径。
